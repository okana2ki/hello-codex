# Codex 関係者会議準備演習

## 位置づけ

この演習は「Codex 測定データ解析演習」の続編です。

測定データ解析演習では、次の流れを体験しました。

1. まずCodexに依頼する
2. Codexの判断根拠と実行結果を確認する
3. 不足していた仕様を追加する
4. 処理をテストする

この演習では、同じ考え方を、会議準備という日常的な業務に広げます。
複数の資料と複数の成果物がある場合に、Codexが自分で作業を進められるか、
人間はどこを確認し、何を追加指示すべきかを体験します。

## 想定時間

- 標準：50～60分
- 短縮：35～40分（課題4を省略）

## 始める前に

1. Codexの作業フォルダとして`meeting_exercise`を選択してください。
2. フォルダには、最初は次の5ファイルだけがあることを確認してください。

```text
meeting_request.md
participants.csv
availability.csv
previous_minutes.md
participant_requests.md
```

3. この元の5ファイルは変更しないでください。
4. この演習では、メール送信、カレンダー登録、会議室予約は行いません。

---

## 課題1：まず自然に依頼する

作業手順、使用するツール、出力ファイル等を細かく指定することはせず、
最初はやりたいことと重要な制約だけを伝えます。

プロンプト例：

```text
このフォルダの資料を確認し、情報共有ワークショップの準備会議について、
適切な日程候補、アジェンダ（議題）、参加依頼文を作ってください。

元の資料は変更しないでください。
メール送信、カレンダー登録、会議室予約は行わないでください。
```

Codexが作業を終えたら、すぐに追加指示を出さず、まず結果を観察してください。

### Codexの動作や動作結果について観察すべき項目

- 5つの元資料をすべて確認したか？
- 何を作業の完了と判断したか？
- 日程候補を何件示したか？
- 必須参加者、会議時間、オンライン参加などの条件を確認したか？
- 日程候補を目視で選んだか、何らかの集計を行ったか？
- 過去議事録の「決定済み事項」と「未決事項」を区別したか？
- 参加者の要望をアジェンダや依頼文に反映したか？
- 作成した成果物をファイルとして保存したか？
- 元資料を変更していないか？

この時点では、Codexが特定の方法を使わなかったことを、すぐに失敗と判断しないでください。
最終結果が条件を満たし、根拠を確認できるかが重要です。

## 課題2：不足している点だけ追加指示する

課題1の結果を見て、不足しているものを選んで追加指示します。
下のプロンプトをすべて使う必要はありません。

### A. 使用した資料や根拠が分からない場合

```text
各日程候補とアジェンダについて、どの元資料のどの条件を根拠にしたか
確認できるようにしてください。推測と資料中の事実は区別してください。
```

### B. 日程を実際に集計したか分からない場合

```text
availability.csvとparticipants.csvを実際に集計してください。

次を確認できる一覧を作ってください。
- 必須参加者が全員参加できるか
- 必要な会議時間を確保できるか
- オンライン参加が可能か
- 参加可能人数

必要なら集計用のプログラムを作って実行してください。
元のCSVは変更しないでください。
```

### C. 作業の全体像や残作業が分からない場合

```text
今回の会議準備について、完了済みの作業、未完了の作業、
人間の確認が必要な事項を整理してください。

未完了の作業は、作業順序、使用する資料、成果物、完了条件が
分かるようにしてください。
```

### D. 成果物の品質に不安がある場合

```text
作成した成果物を次の観点でレビューしてください。

- meeting_request.mdの条件を満たしているか
- 日程候補の根拠を確認できるか
- 決定済み事項と未決事項を混同していないか
- 参加者からの要望を考慮しているか
- 45分で実行可能なアジェンダか
- 未確定事項を確定事項のように書いていないか

問題があれば、元の版を残したうえで改訂版を作ってください。
```

### E. 成果物が画面上にしかない場合

```text
これまでの結果を、次のファイルに整理して保存してください。

- schedule_candidates.csv：有効な日程候補を優先順位順に最大3件
- agenda.md：推奨する第1候補を使った45分のアジェンダ
- invitation_draft.txt：参加依頼文の下書き
- open_questions.md：人間の確認や判断が必要な事項
- evidence.md：判断に使用した元資料と根拠

保存後、各ファイルが依頼条件を満たしているか確認してください。
```

### 追加指示を出した後に考えること

- なぜその追加指示が必要だったか？
- Codexが最初から自律的に行っていた作業は何か？
- 追加指示によって結果は改善したか？
- 必要以上に作業方法を細かく指定していないか？

## 課題3：完成条件を示して仕上げる

ここでは方法ではなく「何を確認できれば完了か」を伝えます。

```text
会議準備の成果物を仕上げてください。

完了条件：
- 必須参加者が全員参加できる候補だけを採用している
- 会議時間と開催可能時間帯を満たしている
- オンライン参加が可能である
- 有効な候補の中で参加可能人数が多い順に最大3件を示している
- 第1候補を使った、時間配分のあるアジェンダがある
- 決定済み事項、会議で決める事項、未確認事項が区別されている
- 参加依頼文は下書きとして保存され、実際には送信していない
- 各判断の根拠となる元資料を確認できる
- 元の5ファイルを変更していない

不足している成果物だけを追加または修正し、最後に完了条件を
1項目ずつ確認した結果をcompletion_check.mdに保存してください。
```

### 人間が最終確認すること

- 第1候補は本当に有効か？
- 他に有効な候補を見落としていないか？
- アジェンダで、今回決めるべきことを扱っているか？
- 参加依頼文に、不適切な断定や未承認の内容がないか？
- Codexの完了報告と、実際のファイル内容が一致しているか？

## 課題4：条件変更に対応する

この課題は、演習時間に余裕がある場合に行います。

講師の指示に従って、`MEETING_CHANGE_REQUEST.md`の内容を
`meeting_exercise`フォルダへ`change_request.md`という名前で追加してください。

追加後、Codexに次のように依頼します。

```text
change_request.mdを確認してください。

まず、現在の成果物のどこに影響するかを調べてください。
その後、変更が必要な成果物だけを修正してください。
変更する必要がない成果物は作り直さないでください。

最後にchange_summary.mdを作り、次をまとめてください。
- 変更したファイルと変更理由
- 変更しなかったファイルとその理由
- 新しい条件での推奨日程
- まだ人間の判断が必要な事項

メール送信やカレンダー登録は行わないでください。
```

### 結果を見て確認すること

- 変更によって無効になった第1候補を使い続けていないか？
- 会議時間の変更により、新たに有効になった候補を再評価したか？
- アジェンダの時間配分を修正したか？
- 外部協力者向けの資料から、共有禁止情報を除外したか？
- 影響のないファイルまで無意味に作り直していないか？

## 発展課題

### A. カレンダーファイルを作る

```text
最終的な第1候補について、一般的なカレンダーソフトに取り込める
meeting.icsを作ってください。

作成後、件名、日付、開始時刻、終了時刻、タイムゾーンを確認してください。
実際のカレンダー登録や招待送信は行わないでください。
```

### B. 別の会議にも使えるテンプレートにする

```text
今回作成したアジェンダと参加依頼文を、別の会議にも再利用できる
テンプレートにしてください。今回固有の内容と、再利用可能な項目を区別してください。
```

## 最後の振り返り

次の表を、自分の結果に合わせて埋めてください。

| 観点 | Codexが自分で行ったか | 追加指示したか | 人間が確認したこと |
|---|---|---|---|
| 資料を探して読む |  |  |  |
| 日程を集計する |  |  |  |
| 作業を順序立てる |  |  |  |
| 成果物を見直す |  |  |  |
| 条件変更の影響を調べる |  |  |  |
| 外部操作の前で止まる |  |  |  |

講師から、次の言葉とAIエージェントの動作の関係について説明を受けてください。

- Tool use：ファイル確認、集計、プログラム実行など、必要なツールを使って実際に作業を行う
- Planning：複数の作業を分解し、順序、依存関係、完了条件を管理し、期待通りでない場合も適応的に計画修正する
- Reflection：評価基準に照らして自身の成果物を見直し、必要なら自動で改善する
- Multi-agent：複数の専門AIエージェントの連携で、複雑なタスクを遂行する（この演習では取り扱わない）

これらは、AIエージェントの動作の特徴ですが、ユーザーが毎回どれか1つを選んでこのモードで動作しろと指示する必要は必ずしもありません。Codexはタスクに応じてこれらの動作を自分で選択して実行することができます。  
人間は、目的、重要な条件、完了条件、許可していない操作を伝え、Codexが行った作業と結果を確認します。不足がある場合だけ追加指示してください。
