# Codex 測定データ解析演習

## 目的
Codexを「コードを書いてくれるチャット」ではなく、
手元のデータとファイルを読み、作業を進める開発エージェントとして体験します。

Codexは、必要なファイルを調べ、プログラムを作成・実行し、
結果を検証しながら作業を進めることができます。

ただし、Codexの判断が仕事の目的に合っているか、
必要な条件を満たしているかは人間が確認する必要があります。

この演習では、
「まず依頼する → 結果を確認する → 不足する条件を追加する」
という使い方を体験します。

## 準備：プロジェクトを作成
この演習用のプロジェクトを作成し、ソースフォルダとしてexerciseフォルダを指定してください。

## 課題1：まずデータを理解する
Codexにexerciseフォルダを調べさせ、measurement.csvがどのようなデータか説明させてください。この段階では、ファイルを変更しないよう指示してください。

プロンプト例：
```
このフォルダの中身を確認し、measurement.csvがどのようなデータか説明してください。まだファイルは変更しないでください。
```

結果を見て確認してください：

- Codexはどのファイルを確認したか？
- 各列の意味と単位を正しく説明しているか？
- データ件数や測定時間を確認したか？
- 欠損値や不自然な値の有無に触れているか？
- ファイルを変更していないか？

## 課題2：基本的な解析プログラムを作る
温度、電流、回転数、振動、電圧について、最小値・最大値・平均値を求めるPythonプログラムをCodexに作らせてください。制約条件を書き添えて下さい。

プロンプト例：
```
温度、電流、回転数、振動、電圧について、最小値・最大値・平均値を求めるPythonプログラムを作ってください。

条件：
- measurement.csv 自体は変更しない
- プログラムを実際に実行する
- エラーがあれば原因を調べて修正する
```

結果を見て確認してください：

- Codexはmeasurement.csvを実際に読み込んだか？
- プログラムを作っただけでなく、実行したか？
- 実行時にエラーがなかったか？ エラーがあった場合は修正したか？
- 最小値・最大値・平均値に明らかに不自然な値がないか？
- 対象とした列に漏れがないか？
- measurement.csvが変更されていないか？
- 何を確認できれば「基本解析が完了した」と言えるか？

## 課題3：「異常」を探させる
まずは条件を細かく指定せず、依頼してみてください。

```
異常と思われる箇所がないか調べてください。
判断基準、調査結果、不明点をinitial_anomaly_report.mdにまとめてください。
```

結果を見て考えてください：
- Codexは何を根拠に異常と判断したか？
- その判断を技術者としてそのまま信用できるか？
- 追加で何を指定すべきか？

さらに確認してください：

- Codexは固定閾値、統計的な外れ、時間変化など、どの考え方を使ったか？
- 判断基準はデータから導いたものか、Codexが仮定したものか？
- 「異常」と「気になる変化」を区別しているか？
- 根拠が不足している箇所を不明点として残しているか？

この段階では、Codexの判断が正解か不正解かを決めるのではなく、
どのような判断をしたかを観察してください。

## 課題4：仕様を与えて判定する
プロンプト例：

```
次の条件のいずれかを満たす測定点を異常として抽出してください。

- vibration_g >= 0.8
- motor_current_A >= 3.0
- rotation_rpm < 1200

異常箇所について、時刻と各測定値が分かる一覧を作ってください。
結果と使用した判定条件をspecified_anomaly_report.mdにまとめてください。

initial_anomaly_report.mdは比較のため変更しないでください。
```

2つのレポートを比較してください：

- Codexが最初に考えた異常と、人間が仕様として与えた異常はどう違うか？
- 課題3で見つかった箇所のうち、課題4の仕様では異常にならない箇所はあるか？
- 課題4の仕様で初めて抽出された箇所はあるか？
- どちらか一方だけが正解と言えるか？
- 実際の仕事では、誰が異常の定義を決めるべきか？

## 課題5：検証する
Codexに、作成した異常判定処理が仕様通りかテストさせてください。境界値（例：0.799, 0.800, 0.801）も含めるよう依頼してください。

プロンプト例：

```
作成した異常判定処理が仕様通りかテストしてください。

条件：
- 振動の境界値として0.799、0.800、0.801を含める
- 電流と回転数についても、閾値の直前、閾値と同じ値、閾値を超えた値を含める
- 複数の異常条件を同時に満たす場合も確認する
- テストを実際に実行する
- テスト結果をtest_report.mdに保存する
```

テスト結果を確認してください：

- 0.799は正常、0.800と0.801は異常になっているか？
- 電流と回転数についても境界値が正しく判定されているか？
- 複数条件を同時に満たす場合も正しく処理されているか？
- テストを作っただけでなく、実際に実行したか？
- すべてのテストが成功したことを何から確認できるか？
- 仕様そのものが妥当かどうかは、テストだけで判断できるか？

## 発展課題（時間と利用枠に余裕がある人）
次から1つ以上選んでください。

A. 測定値を時系列グラフにし、異常区間が分かるようにする。  
B. 解析結果をCSVまたはHTMLレポートとして保存する。  
C. 別のCSVにも使えるようにする。  
D. 異常判定の閾値を、コードを書き換えず変更できるようにする。  
E. 固定閾値以外の異常検出方法を提案・実装し、誤検出の可能性も説明させる。  
F. ブラウザでCSVを選ぶだけで解析できる簡単なツールにする。  
G. 技術者向けの報告書にまとめさせる。

## 最後に考えること
「よいプロンプトを書く」よりも、
「何を正常／異常とみなし、何を確認できれば仕事が完了したと言えるか」
を明確にすることが重要です。

## この演習で体験した仕事の進め方

1. まず、やりたいことをCodexに依頼する
2. Codexがどの資料と道具を使ったか確認する
3. 結果の根拠と、作業を実行した証拠を確認する
4. 仕事上必要な条件が不足していれば追加する
5. 完了条件を示して検証させる
6. 最終的な判断は人間が行う

Codexへの依頼では、最初から完璧なプロンプトを書く必要はありません。
結果を確認しながら、必要な条件を追加していくことが重要です。

また、Codexがテストを実行してすべて成功したとしても、
人間が与えた仕様自体が仕事の目的に合っているとは限りません。
Codexには処理と検証を任せつつ、判断基準と完了条件は人間が確認してください。
